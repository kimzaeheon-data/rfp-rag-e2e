2026-11-08에 개인 OpenAI API를 연결해 실제 `/chat` 경로를 평가했습니다. 조건 추출부터 최종 응답까지 성공한 질문은 **15/24개(62.5%)**였습니다.

### 평가 범위

- FastAPI `TestClient`로 `POST /chat`을 호출하고 실제 LangGraph 경로를 실행했습니다.
- 질문마다 새로운 대화로 시작했고, 검색 모드는 `agentic_rag`였습니다.
- 조건 추출은 실제 `gpt-5-nano`를 사용했습니다. 서비스의 10초 타임아웃과 SDK 재시도 0회 설정을 유지했습니다.
- 조회 인덱스는 실제 RFP 100건에서 추출한 사업 정보 요약 100개로 구성된 BGE-M3 FAISS였습니다. 전체 14,606개 청크가 들어 있는 인덱스를 사용한 평가는 아닙니다.
- 전수 조회 경로는 코드가 목록·건수 응답을 구성합니다. 이 경로에는 별도의 LLM 답변 생성 호출이 없습니다.
- 평가 질문 24개와 정답을 실행 전에 저장했습니다. 서비스의 필터 함수를 재사용하지 않고 원본 사업 정보에서 정답 사업 ID와 미확인 건수를 계산했습니다. 예산 조건 3개는 기존 골든셋 Q021–Q023의 정답 ID와도 일치했습니다.
- 원본 14,606개 청크를 검사한 결과, 같은 사업에 속한 청크의 기관·예산·공개일·입찰 시작일·마감일 정보는 모두 일치했습니다.

질문에는 전체 목록·건수, 기관 조건, 예산 범위와 초과·미만 경계, 날짜 범위, 복합 조건, 정렬, 결과 0건, 미지원 조건, 같은 조건의 다른 표현을 포함했습니다.

### 채점 기준

지원되는 질문은 반환 사업 ID의 누락·오포함·중복, 답변 건수, 미확인 건수, 목록의 사업명·기관·예산, 요청한 정렬, 최종 검증 플래그를 확인했습니다. 조건 추출기의 조회 범위 분류도 정답과 일치해야 종단간 성공으로 집계했습니다.

미지원 질문은 조건 추출기가 `unsupported`로 분류하고, 서비스가 조회를 거부하며, 사업 목록을 반환하지 않아야 성공으로 집계했습니다. API 오류로 우연히 올바른 거부 응답이 나온 경우는 최종 응답 정확도에만 포함했습니다.

### 재현

```bash
python -m backend.evaluation.evaluate_catalog \
  --chunks <원본_전체_청크_JSON_경로> \
  --index data/experiment/metadata_ab_index \
```
